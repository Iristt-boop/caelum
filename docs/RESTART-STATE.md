## 一、先说结论：重启不是一件事，是两件

代码里几乎每一条「不落盘」的注释，理由都长这样：

> 重启会重置回默认，这是有意的：隔了一天再开口，本来也该是平常状态。
> —— `nox-core/nox.py:364`

这个理由**默认了「进程重启 ≈ 隔了很久 / 对话结束了」**。

但 2026-09-13 一天之内 nox-core 重启了 **8 次，全部是发版本造成的**。
发版本的重启大概几十秒，她那头可能一句话还没说完。

所以要分开看：

| | 间隔 | 她的感受 | 原注释的理由 |
|---|---|---|---|
| **休息式重启** | 几小时～一天 | 本来就该是新的开始 | ✅ 成立 |
| **部署式重启** | 几十秒 | 他刚才还在，忽然不记得了 | ❌ 不成立 |

**判断一条状态该不该落盘，问的不是「要不要留」，而是「隔多久之后它就不该留了」。**
这是下面整张表的轴。

## 三、已经有现成的地方可以落

**不要新起一套。** `attention/store.py:248/263` 已经有一个带锁的 JSON 键值表：

```python
store.get_source_state(key) -> dict | None   # 坏了返回 None，不会让他起不来
store.set_source_state(key, value)           # UPSERT + commit
```

`presence` / `scheduler` / `gate` / `threads` / `ledger` 全都走它。
mood 要落盘就落这里 —— 再开一张表就是 `CAELUM-MAP` 里那条
「平行实现反复长出来」。

⚠️ **时序坑**：`attention` 是在 `api/server.py` 的 `_build_attention` 里造的，
那时候 `Nox.__init__` 早跑完了。所以拿 store 必须用**取值函数**
（`lambda: getattr(self, "attention", None)`），不能在 `__init__` 里直接取 ——
`ResonanceProvider` / `UnderstandingProvider` / luckin 的 `store_ref` 都是这么写的。

## 四、落盘之后怎么验

按 2026-09-13 立的规矩（`CAELUM-MAP.md` 第三·五节）：**改完必须故意改坏一次。**

这件事上的改坏方式和判据：

| 改坏 | 必须红的检查 |
|---|---|
| 把 `set_source_state` 那行注掉 | 「重启后 valence 保持」的测试 |
| 把恢复时的时间判断写死成永远恢复 | 「隔了 12 小时应回默认」的测试 |
| 把 store 取值函数换成 `__init__` 里直接取 | 恢复静默失效 —— **这条最容易假绿**，因为拿不到 store 的分支多半是 `return` 掉的，不抛错 |

最后一条要特别当心：**它的失败形状是"什么都没发生"**，
正好是交接里五种假验证的第五种（检查没覆盖被改的东西）。
判据必须是「读回来的 valence == 存进去的值」，不能是「调用没抛异常」。

### 实际跑下来（2026-09-14）

`scratch/mutate-restart-state.py`，11 条变异 **11 条全红**。过程里抓到两件事，
都是"测试绿了但什么都没验"，**靠全绿一条都发现不了**：

1. **空断言。** 守「第一轮就恢复」那条原本写的是 `"难过" in rendered` ——
   而 `MOOD_INSTRUCTION` 里本来就有「从 开心/难过/烦躁/… 里选一个」，
   这个匹配**恒为真**。把 `_dynamic` 里的恢复整个删掉它照样绿。
   判据换成 `"看起来是「难过」"`（只有恢复了才会出现的那句）才立住。

2. 🔴 **`.pyc` 被变异体污染。** 变异脚本写回源码的时刻和 pytest 写 `.pyc`
   的时刻落在同一秒，而 Python 判断 `.pyc` 过期是**秒级**比对 mtime ——
   于是磁盘上留下的是**变异体的字节码**，之后每一次运行都在跑被改坏的版本。
   症状极阴：`inspect.getsource()` 读 `.py` 显示新代码，执行的却是旧的，
   "代码明明在那儿却不执行"。
   **跑变异测试必须 `PYTHONDONTWRITEBYTECODE=1` + 开跑前清 `__pycache__`。**
