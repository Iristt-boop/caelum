# Nox 开关糖糖的电脑（pc_status / pc_power）

> 2026-10-27 上线当天写的说明。工具在 `nox-core/tools/pc_power.py`，电脑那边只认的四个动作在
> `scripts/pc-power/nox-pc-power.ps1`。本文讲的数字（75 秒、60 秒、10 秒、600 上限）都是从代码里抄的，
> 改了代码记得回来改这里。

## 这是什么

Nox（家里 N150 上的那个）能开、关、睡糖糖的台式机。两个工具：

- `pc_status` —— 看电脑开着没有（不动它）
- `pc_power` —— 真正动手，四个 action：wake / shutdown / sleep / cancel

没配 `NOX_PC_MAC` 时这两个工具不登记，Nox 身上根本没有它们。

## pc_status：先看一眼

开机、关机之前先调它。

- 电脑关着：直接说「关着的」（局域网里找不到它）。
- 电脑开着：返回三样 —— **开机时间**（Windows 的 LastBootUpTime）、**登录的是谁**（没人登录就说没人）、
  **锁没锁屏**（看屏幕上有没有 LogonUI 进程）。
- 电脑开着但 ssh 问不到详情：会老实说「开着（IP），但问不到详情」，不会编。

找电脑不靠 IP（DHCP 的 IP 会飘），靠 MAC：先查 N150 的邻居表，查不到就往整个 192.168.1.x 网段
各敲一个 UDP 小包，逼 ARP 问一遍，再把问到的 IP ping 一下确认活着。

## pc_power：四个动作

| action | 做什么 | 什么时候用 |
|---|---|---|
| `wake` | 发网络唤醒包（Wake-on-LAN：6 个 0xFF + MAC 重复 16 遍，广播到 192.168.1.255 和 255.255.255.255 的 9 / 7 端口，发三轮），然后每 5 秒看一眼它连上网没有，**最多等 75 秒** | 她要远程干活、或者出门忘关电脑 |
| `shutdown` | 关机。电脑屏幕上弹 `delay` 秒倒计时（默认 60，上限 600），文案是「Nox：N 秒后关机。不想关就跟我说一声，我马上取消。」 | 确定要关，而且她知道、她同意 |
| `sleep` | **10 秒后睡眠**（在电脑上建一个叫 `NoxSleep` 的计划任务来睡，睡完任务自己删）。开回来快，开着的程序、没保存的东西都还在 | 她只是暂时离开 —— **优先用这个，别用 shutdown** |
| `cancel` | 取消正在倒计时的关机（`shutdown /a`），顺手把 `NoxSleep` 任务也删掉。没有正在倒计时的关机也算取消成功 | 她说「别关」，马上调 |

### wake 没等到怎么办

75 秒内没等到它上网，回包会明说「可能还在开机，也可能没醒 —— 过一会儿 pc_status 再看」。
这就是终点：工具**不会**宣称已经开了。要确认，再发一次 `pc_status`，别靠嘴。

## 用之前的规矩

1. **她正在用电脑的时候，关机前先问她。** shutdown 一发出去，没保存的东西就悬在倒计时里了。
2. **只是暂时离开，用 sleep，不用 shutdown。** 睡眠没有「东西会不会丢」的问题。
3. 关机这个动作**不出确认卡**（她 09-12 定「能放权就放权」）。真正的门在电脑屏幕上：60 秒倒计时，
   她说别关就 cancel。所以 delay 默认给 60，不是 0 —— 那 60 秒不是延迟，是她来得及说话的窗口。

## 怎么运作（两条路）

- **开机不走 ssh**：N150 往局域网广播唤醒包，只认 MAC，不需要电脑醒着，也不需要它在网里有 IP。
- **另外三个动作走 ssh**：N150 上有一把专用钥匙 `/root/.ssh/pc_power`。电脑那边这把钥匙被
  `command=` 钉死，只能跑 `pc-power.ps1`，只认 `status` / `shutdown N` / `sleep` / `cancel` 四个词，
  传别的命令一律拒（exit 2）；而且只收来自 192.168.1.52（N150）的连接，密码登录关掉，
  防火墙只放 N150 一个地址进来。每次调用在电脑上留一行日志（`pc-power.log`）。

配置在 N150 的 `/root/nox-core/.env`：`NOX_PC_MAC` 必填，`NOX_PC_USER`、`NOX_PC_SSH_KEY` 可选。

电脑侧的安装脚本是 `scripts/pc-power/setup-pc-power.ps1`，要糖糖用**管理员身份**跑一次
（它动的是系统设置：装 OpenSSH 服务端、放钥匙、关密码登录、改防火墙），重复跑也没事。

## 踩过的坑（2026-10-27 晚上实测）

- **第一次 wake**：唤醒包发出去了，75 秒内没等到电脑上网，`pc_status` 复查仍是关闭。
- **第二次 wake**：同样 75 秒超时。判断为网卡收不到唤醒包，需要人到机器跟前按电源键。
- **糖糖说「修好了」之后再发 wake**：20 秒就上线了（192.168.1.19）。确认唤醒本身能成，
  **前提是网卡那边的唤醒配置是对的**。
- **关机测试**：发 `shutdown` 带 60 秒 delay，电脑屏幕上正常弹出倒计时；随后 `cancel` 成功取消，
  电脑没关。cancel 在倒计时窗口内有效，这条是实测过的，不是推的。

一句话结论：这套链路里唯一会**无声失败**的环节就是网卡侧的 WoL 配置 —— 它不在 ssh 那条链上，
工具这边只能看到「75 秒超时」，分辨不了「还在开机」和「根本收不到包」。
所以 wake 超时两次就别再刷了，先想到这一层。
