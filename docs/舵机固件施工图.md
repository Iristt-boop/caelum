## 构建（必须用 Docker ESP-IDF，无本地 idf.py）
前置：Windows 装 Docker Desktop（拉 espressif/idf:v5.5.2，几个 G）；保留 esptool.exe；装 pyserial 做串口监视。

```
# 克隆 + 子模块
git clone --recursive https://github.com/kisaragi-mochi/stackchan-mcp
# 若漏子模块：git submodule update --init firmware/components/smooth_ui_toolkit
# 生成表情图（不做会露出中文占位界面）
cd firmware && python scripts/avatar_convert/convert_avatars.py

# 构建（stackchan 参数强制，否则选错板型会 PSRAM 引导死循环）
docker run --rm --cpus=4 --ulimit nofile=65536:65536 \
  -v "$PWD":/project -w /project espressif/idf:v5.5.2 \
  python ./scripts/release.py stackchan
```

## 服务器地址配置（关键）
在 `firmware/sdkconfig.defaults.local`（gitignore，不提交）里写：
```
CONFIG_DEFAULT_WEBSOCKET_URL="ws://43.133.211.140:8010/xiaozhi/v1/"
CONFIG_FORCE_DEFAULT_WEBSOCKET_URL=y
# 令牌：我们的 xiaozhi-server 未启用 token，先留空或不写，看握手日志再定
```
FORCE 模式必须开——否则设备会用 NVS 里旧固件残留的 WS 地址（会连去 api.tenclass.net）。

## 刷写（保留配网，不清 NVS）
```
esptool.exe --chip esp32s3 --port COM3 -b 460800 \
  --before default_reset --after hard_reset \
  write_flash 0x20000 build/xiaozhi.bin
```
> 刷到 0x20000（不是 0x0）→ 保住 NVS，WiFi 配网大概率不用重配。
> 千万别把 merged-binary 刷到 0x0（会盖引导区、丢 NVS）。

## ⚠️ 最大不确定点（决定成败）
这个分支原本是配**它自家的 Python 网关（端口 8765 + token）**用的，不是直接对 xiaozhi-server。
- 好消息：固件走的是标准 xiaozhi WS 协议，用标准 `CONFIG_DEFAULT_WEBSOCKET_URL` 配地址 → 理论上能指到我们的 8010 服务器
- 需一次试刷验证：握手（hello/mcp/tts）能不能和我们服务器对上、token 要不要
- **意外之喜**：若连通，固件会把 `move_head` / `set_avatar` 这些暴露成 MCP 工具 → 我们已开的 function_call 能让 Nox **听指令转头**（"转过头来看我"），比出厂那种被动摆头更强

## 风险与回退
- 需要装 Docker（占空间、初次拉镜像慢）
- 试刷可能要反复调 URL / token / 路径
- 最坏情况：刷回现在这版通用固件（二进制已在手，恢复即可），不影响已跑通的语音系统
