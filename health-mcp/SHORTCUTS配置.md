# iPhone 快捷指令配置指南

> 目标：每天早上（或任意触发）把 **昨天** 的 Apple Health 数据上传到 VPS，Agent 通过 MCP 读取。
>
> 为什么取「昨天」：触发时间不确定（可能睡到 10 点），昨天的数据一定完整。

---

## 0. 先测试 VPS 连通性

新建一个测试快捷指令：

| 动作 | 配置 |
|------|------|
| 获取 URL 内容 | URL: `https://你的域名/health/ping`，方法: `GET` |
| 显示结果 | 内容: `URL 的内容` |

运行后若弹出 `{status: ok, time: ...}`，说明网络通。再开始配主快捷指令。

---

## 1. 构造昨天的时间窗口

用「调整日期」的「**获取一天的开始**」（有些系统显示为「获取哪天开始」）直接拿到今天 00:00:00，再往前推一天得到昨天 00:00:00。

| 顺序 | 动作 | 配置 |
|------|------|------|
| 1 | 当前日期 | （无需配置） |
| 2 | 调整日期 | 当前日期 → **获取一天的开始**（或「获取哪天开始」） |
| 3 | 设定变量 | 变量名: `todayStart` = 调整后的日期 |
| 4 | 调整日期 | `todayStart` → **减去 1 天** |
| 5 | 设定变量 | 变量名: `startDate` = 调整后的日期 |
| 6 | 设定变量 | 变量名: `endDate` = `todayStart` |
| 7 | 格式化日期 | 输入: `startDate`，格式: `yyyy-MM-dd` |
| 8 | 设定变量 | 变量名: `yesterdayDateString` = 格式化后的日期 |

> 结果：
> - `startDate` = 昨天 00:00:00
> - `endDate` = 今天 00:00:00
> - `yesterdayDateString` = `2026-07-27`（POST 的 `date` 字段用）
>
> 后面所有健康样本都用 `开始日期 介于 startDate 和 endDate` 查询，正好覆盖昨天一整天。
>
> 注意：部分 iOS 版本的「文本 → 日期」动作会被解释为「查找下一个重复日程」，对过去的时间点会报「请选择其他日程」。这里直接用「调整日期」绕开该问题。

---

## 2. 步数

| 顺序 | 动作 | 配置 |
|------|------|------|
| 15 | 查找健康样本 | 类型: **步数**；筛选: `开始日期 介于 startDate 和 endDate` |
| 16 | 计算 | `健康样本` 的 **总和**（点变量标签 → 显示为 → 值） |
| 17 | 设定变量 | 变量名: `steps` = 计算结果 |

> 如果你的 iOS 版本「计算」里没有「总和/平均值」等统计运算，改用循环累加：
> 1. 数字 `0` → 设定变量 `steps`
> 2. 重复每一项（内容: 健康样本）
> 3. 计算: `steps + 重复项目`（点重复项目标签 → 显示为 → 值）
> 4. 设定变量 `steps` = 计算结果
> 5. 结束重复

## 3. 活动能量

| 顺序 | 动作 | 配置 |
|------|------|------|
| 18 | 查找健康样本 | 类型: **活动能量**（Active Energy）；窗口 `startDate` → `endDate`；**单位: 千卡** |
| 19 | 计算 | 总和（显示为: 值） |
| 20 | 设定变量 | 变量名: `activeEnergy` = 计算结果 |

## 4. 步行 + 跑步距离

| 顺序 | 动作 | 配置 |
|------|------|------|
| 21 | 查找健康样本 | 类型: **步行 + 跑步距离**（Walking + Running Distance）；窗口同上；**单位: 公里** |
| 22 | 计算 | 总和（显示为: 值） |
| 23 | 设定变量 | 变量名: `distance` = 计算结果 |

> 如果快捷指令里只能用「米」做单位，VPS 存入前会自动除以 1000。

## 5. 心率

| 顺序 | 动作 | 配置 |
|------|------|------|
| 24 | 查找健康样本 | 类型: **心率**（Heart Rate）；窗口同上 |
| 25 | 计算 | 平均值 → 设定变量 `avgHeartRate` |
| 26 | 计算 | 最小值 → 设定变量 `minHeartRate` |
| 27 | 计算 | 最大值 → 设定变量 `maxHeartRate` |

> 同样，如果没有统计运算，用循环累加/比较实现。或者只取「最后一项」作为简化方案。

## 6. 静息心率

| 顺序 | 动作 | 配置 |
|------|------|------|
| 28 | 查找健康样本 | 类型: **静息心率**（Resting Heart Rate）；窗口同上 |
| 29 | 获取列表中的项目 | **最后一项**（点标签 → 显示为 → 值） |
| 30 | 设定变量 | 变量名: `restingHeartRate` = 结果 |

> 没有 Apple Watch 可能没有静息心率数据，留空即可。

## 8. 睡眠分析（推荐：原样上传，后端解析）

睡眠分期判断在快捷指令里很啰嗦。现在**后端已经支持直接解析原始睡眠样本**，前端只需要把每个睡眠样本的 `value`、`startDate`、`endDate` 原样传上来就行。

### 8.1 查询睡眠样本

| 顺序 | 动作 | 配置 |
|------|------|------|
| 33 | 查找健康样本 | 类型: **睡眠分析**（Sleep Analysis）；窗口 `startDate` → `endDate` |
| 34 | 设定变量 | 变量名: `sleepSamples` = 健康样本 |

### 8.2 拼睡眠 JSON 数组

| 顺序 | 动作 | 配置 |
|------|------|------|
| 35 | 文本 | 内容: `[` |
| 36 | 设定变量 | 变量名: `sleepJson` = 上面的文本 |
| 37 | 重复每一项 | 内容: `sleepSamples` |
| 38 | 文本 | 内容里先插入变量 `sleepJson`，再输入 `{"value":"[重复项目的值]","startDate":"[重复项目的开始日期]","endDate":"[重复项目的结束日期]"},` |
| 39 | 设定变量 | 变量名: `sleepJson` = 上面的文本 |
| 40 | 结束重复 | |
| 41 | 文本 | 内容里先插入变量 `sleepJson`，再输入 `]` |
| 42 | 设定变量 | 变量名: `sleepJson` = 上面的文本 |
| 43 | 替换文本 | 在 `sleepJson` 中，把 `},]` 替换成 `}]` |
| 44 | 设定变量 | 变量名: `sleepJson` = 替换后的文本 |

> 注意：
> - Shortcuts 里没有 `A + B` 写法，文本拼接就用「文本」动作把多个变量/文字片段按顺序放进去。
> - 第 38 步里，`sleepJson` 是已有变量（蓝色标签），后面紧跟 JSON 片段；`[重复项目...]` 是循环里的魔术变量。
> - JSON 键名 `"value"`、`"startDate"`、`"endDate"` 必须带英文双引号。
> - 如果「重复项目的开始日期」显示为带时区的完整时间（如 `2026-07-29T23:00:00+08:00`），直接传，后端能解析。

## 9. 拼 JSON 并 POST 到 VPS

### 9.1 拼 JSON 文本

添加一个「文本」动作，内容如下（直接复制粘贴，然后**把所有 `[变量名]` 替换成真正的蓝色变量标签**）：

```json
{
  "date": "[yesterdayDateString]",
  "steps": [steps],
  "activeEnergy": [activeEnergy],
  "distance": [distance],
  "avgHeartRate": [avgHeartRate],
  "minHeartRate": [minHeartRate],
  "maxHeartRate": [maxHeartRate],
  "restingHeartRate": [restingHeartRate],
  "hrv": [hrv],
  "sleepSamples": [sleepJson]
}
```

> **所有 `[变量名]` 整体都要替换成蓝色变量标签，包括方括号一起删掉。**
>
> 但 `sleepSamples` 这行要额外注意：因为 `sleepJson` 变量本身的内容已经是带方括号的完整数组 `[{"value":"Core",...}]`，所以替换后应该是：
>
> ```json
> "sleepSamples": Sleepjson
> ```
>
> 即**不要保留 `sleepJson` 外面的方括号**，否则会变成 `"sleepSamples": [[...]]`（双层数组，非法 JSON）。

### 9.2 设定变量

| 动作 | 配置 |
|------|------|
| 设定变量 | 变量名: `jsonPayload` = 上面的 JSON 文本 |

### 9.3 POST

| 动作 | 配置 |
|------|------|
| 获取 URL 内容 | 方法: `POST` |
| | URL: `https://你的域名/health/sync` |
| | 请求体: 选 `文件` 或 `JSON`，填入变量 `jsonPayload` |
| | 标头: 添加一项 `X-Auth-Token`，值为你在 VPS 设置的 `HEALTH_SYNC_TOKEN` |

> 快捷指令里「获取 URL 内容」的请求体，如果支持「JSON」模式就直接选 JSON 并把文本填进去；否则选「文件」模式 + `jsonPayload` 变量也可以。

### 9.4 调试通知（可选）

| 动作 | 配置 |
|------|------|
| 显示通知 | 标题: `健康数据同步`，内容: `URL 的内容` |

跑稳之后可以删掉，让快捷指令静默运行。

## 10. 自动化触发

去「自动化」页签，新建 3 个自动化，都选择「运行快捷指令」→ 指向上面建好的快捷指令，并**关闭「运行前询问」**：

| 触发器 | 说明 |
|--------|------|
| 每天 09:00 | 常规兜底 |
| 闹钟停止时 | 最靠谱，醒来就执行 |
| 睡眠专注模式关闭时 | 辅助兜底 |

## 常见问题

| 现象 | 原因 / 解法 |
|------|------------|
| 快捷指令运行后没数据 | 检查健康 App 是否已授权快捷指令读取对应类型：设置 → 健康 → 数据访问权限与设备 → 快捷指令 → 全部打开 |
| 步数为 0 | 确认「查找健康样本」的窗口是 `startDate` 到 `endDate`，且两个都是蓝色变量标签 |
| 活动能量/距离为 0 | 检查类型是否选对（不是「膳食能量」），单位是否正确 |
| 距离差 1000 倍 | 快捷指令单位用了「米」。后端会自动识别并除以 1000，也可在快捷指令里改成「公里」 |
| 睡眠分期全是 0 | 检查「如果」条件里的分期名称：中文系统用「深睡/快速眼动/核心/清醒」，英文系统用「Deep/REM/Core/Awake」 |
| VPS 返回 401 | `X-Auth-Token` 与 VPS 环境变量 `HEALTH_SYNC_TOKEN` 不一致 |
| VPS 返回 422 | JSON 字段名写错，或某个数字字段传了文本。检查 `date` 是字符串且格式为 `yyyy-MM-dd` |
| 快捷指令报「找不到所选日程的下一个日期」 | 部分 iOS 的「文本 → 日期」动作被解释成「查找下一个重复日程」。别用它——按 ① 用「调整日期 → 获取一天的开始」构造零点 |
